# Technology Stack

**Analysis Date:** 2026-06-02

## Languages

**Primary:**
- TypeScript ^6.0.2 (`strict`, `verbatimModuleSyntax`, `moduleResolution: bundler`) - all app code under `src/` and `server/`, configured in `tsconfig.json`
- TSX/JSX (`jsx: react-jsx`) - React UI in `src/`, `tsconfig.json`

**Secondary:**
- JavaScript (ESM) - production bootstrap in `scripts/start-production.mjs`
- SQL - Drizzle migrations under `drizzle/` (generated by `drizzle-kit`, `drizzle.config.ts`)
- CSS / Tailwind v4 - `src/` styles compiled via `@tailwindcss/vite` (see `vite.config.ts`)

## Runtime

**Environment:**
- Dev/build: Bun 1 (Alpine) — `Dockerfile` `deps` and `build` stages use `oven/bun:1-alpine`
- Production server: Node.js 22 (Alpine) — `Dockerfile` `runtime` stage uses `node:22-alpine`, started via `node scripts/start-production.mjs`
- Module type: ESM (`"type": "module"` in `package.json`)

**Package Manager:**
- Bun (lockfile-pinned), enforced via `bun install --frozen-lockfile` in `Dockerfile` and `.github/workflows/ci.yml`
- Lockfile: present — `bun.lock` (the `AGENTS.md` explicitly forbids `npm`/`pnpm` and `bun test`)

## Configuration

**Environment:**
- `.env` loaded automatically by `justfile` (uses `just`'s built-in dotenv); `.env.example` lists `DATABASE_URL`, `ENCRYPTION_KEY`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`
- `drizzle.config.ts` throws at import time if `DATABASE_URL` is missing
- `server/auth.ts` throws when `BETTER_AUTH_URL`/`BETTER_AUTH_SECRET` are missing in non-development
- `server/db/index.ts` reads `DB_POOL_MAX` (default `5`)
- `compose.yaml` additionally consumes `RESEND_API_KEY`, `RESEND_FROM`, `TRUSTED_PROXY_COUNT`, `APP_IMAGE`, `APP_PORT`, `POSTGRES_*`

**Build:**
- `vite.config.ts` - dev/build/test config (single source for Vite + Vitest)
- `tsconfig.json` - includes `src/**/*`, `server/**/*`, `scripts/**/*`, `drizzle.config.ts`, `vite.config.ts`; path aliases `#/*` and `@/*` → `./src/*`
- `biome.json` - Biome 2.4.16 (`!dist`, `!src/routeTree.gen.ts`, `!drizzle`)
- `drizzle.config.ts` - PostgreSQL dialect, schema `./server/db/schema.ts`, output `./drizzle`
- `components.json` - shadcn registry config for `src/components/ui/`
- `Dockerfile` - multi-stage (Bun deps/build → Node runtime); copies only `dist/`, `node_modules/`, `drizzle/`, `scripts/start-production.mjs`, and the schema needed for runtime migrations
- `compose.yaml` - app + `postgres:17-alpine` + `axllent/mailpit` for local SMTP capture
- `app.json` - liveness/startup healthchecks targeting `/api/health` (for Dokku)

## Platform Requirements

**Development:**
- Bun (any 1.x); `bun run dev` serves Vite on port 3000 (`AGENTS.md`)
- A reachable PostgreSQL instance (Drizzle config and auth bootstrap both require `DATABASE_URL`); `compose.yaml` provides one alongside Mailpit on ports 1025/8025
- macOS/Linux assumed (`justfile` recipes use `bash`); native SSH deps (`ssh2`, `cpu-features`) compile via `node-ssh`

**Production:**
- Two supported deploy targets, selected by `vars.DEPLOY_TARGET` in `.github/workflows/deploy.yml`:
  - **VPS via Docker Compose** - image built and pushed to GHCR (`ghcr.io/<repo>`), copied to the VPS, then `docker compose run --rm app ./node_modules/.bin/drizzle-kit migrate` runs migrations before `docker compose up -d app`
  - **Dokku** - `git push dokku HEAD:master` after `dokku config:set` syncs env vars
- Runtime is Node 22 Alpine serving compiled `dist/server/server.js` plus static `dist/client/*` via `scripts/start-production.mjs`
- Expects a TLS-terminating reverse proxy in front (Caddy/nginx) - `requireHttps()` in `server/app.ts` rejects plain-HTTP credentialed requests in production, trusting `x-forwarded-proto`; `TRUSTED_PROXY_COUNT` (default `1`) controls forwarded-IP parsing
- Healthcheck endpoint `/api/health` is used by both `Dockerfile` HEALTHCHECK and `app.json`
