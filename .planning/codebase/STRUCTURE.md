# Codebase Structure

**Analysis Date:** 2026-05-31

## Directory Layout

```text
hermes-hub/
├── src/ # Frontend app (TanStack routes, UI components, feature modules, shared client/server types)
│   ├── routes/ # File-based route pages (`/`, `/login`, `/dashboard`, `/servers/*`, `/ai-provider`, `/telegram`, `/logs`, etc.)
│   ├── features/ # Domain UI modules (dashboard, servers, providers, telegram, logs)
│   ├── components/ # Shared UI shells and primitives (`Header`, `Footer`, `ui/button`)
│   ├── lib/ # Frontend helpers/types and server-call wrappers (`session`, `auth-client`, type contracts)
│   ├── router.tsx # TanStack router factory
│   ├── routeTree.gen.ts # Generated route map
│   └── server.ts # Unified request dispatcher (SSR vs `/api`)
├── server/ # Backend API and domain logic (Hono routes, auth, SSH workflows, DB access)
│   ├── app.ts # API route registration under `/api`
│   ├── db/ # Drizzle schema/connection/health checks
│   ├── install/ # Install stream state and SSE helpers
│   ├── lib/ # Backend helper utilities (email send, client IP)
│   └── *.ts # Domain services (servers/install/actions/dashboard/providers/telegram/logs/security)
├── drizzle/ # SQL migrations and metadata generated by Drizzle
├── docs/ # API reference, ADRs, and architecture notes
├── scripts/ # Runtime/startup scripts (`start-production.mjs`)
├── public/ # Static assets served by frontend build
├── compose.yaml # Local full-stack services (app + postgres + mailpit)
├── Dockerfile # Multi-stage production image build/runtime
├── drizzle.config.ts # Drizzle migration configuration
├── vite.config.ts # Vite + TanStack Start + test config
└── package.json # Scripts and dependencies
```

## Directory Purposes

**src/:**
- Purpose: Client-facing app and route composition for authenticated/unauthenticated flows.
- Contains: Route files, feature UI components, reusable UI primitives, frontend type contracts and utilities.
- Key files: `src/server.ts`, `src/router.tsx`, `src/routeTree.gen.ts`, `src/routes/__root.tsx`, `src/routes/dashboard.tsx`, `src/features/servers/install-progress.tsx`, `src/lib/session.ts`.

**server/:**
- Purpose: REST API handlers and backend orchestration for SSH operations, installs, provider/telegram deploy, dashboard aggregation, and logging.
- Contains: Hono app, auth integration, DB schema access, domain modules, SSE stream state helpers.
- Key files: `server/app.ts`, `server/auth.ts`, `server/servers.ts`, `server/install.ts`, `server/server-actions.ts`, `server/dashboard.ts`, `server/providers.ts`, `server/telegram.ts`, `server/logs.ts`, `server/install/sse-stream.ts`, `server/db/schema.ts`.

**server/db/:**
- Purpose: Data model and DB connectivity.
- Contains: Drizzle schema, DB singleton factory, health query helper.
- Key files: `server/db/schema.ts`, `server/db/index.ts`, `server/db/health.ts`.

**src/routes/:**
- Purpose: Define URL-to-page mapping and route-level loaders/guards.
- Contains: Public pages and authenticated application pages.
- Key files: `src/routes/index.tsx`, `src/routes/login.tsx`, `src/routes/dashboard.tsx`, `src/routes/servers.index.tsx`, `src/routes/servers.new.tsx`, `src/routes/servers.$id.tsx`, `src/routes/servers.$id.install.tsx`, `src/routes/ai-provider.tsx`, `src/routes/telegram.tsx`, `src/routes/logs.tsx`, `src/routes/settings.tsx`, `src/routes/about.tsx`.

**src/features/:**
- Purpose: Feature-scoped UI logic and API interaction states.
- Contains: Per-domain React components for dashboard polling, server CRUD/install flow, provider settings, telegram settings, logs viewer.
- Key files: `src/features/dashboard/status-overview.tsx`, `src/features/servers/server-detail.tsx`, `src/features/servers/connection-wizard.tsx`, `src/features/servers/install-progress.tsx`, `src/features/providers/provider-settings.tsx`, `src/features/telegram/telegram-settings.tsx`, `src/features/logs/logs-viewer.tsx`.

**docs/:**
- Purpose: Architectural decisions and API documentation.
- Contains: ADRs, endpoint reference, review notes.
- Key files: `docs/api-reference.md`, `docs/adr/0001-tanstack-start-with-hono-api.md`, `docs/adr/0003-better-auth-with-magic-link.md`, `docs/adr/0005-aes-256-gcm-credential-encryption.md`.

## Key File Locations

**Entry Points:**
- `src/server.ts`: Unified request entry that routes `/api/*` to Hono and everything else to TanStack SSR.
- `server/app.ts`: Central API route binding layer.
- `src/router.tsx`: Router creation using generated route tree.
- `scripts/start-production.mjs`: Production Node runtime entry (migrations + static serving + request proxying).

**Configuration:**
- `package.json`: App scripts (`dev`, `build`, `test`, `typecheck`, `db:generate`) and dependencies.
- `vite.config.ts`: Vite plugin stack and Vitest include globs.
- `drizzle.config.ts`: Migration output path and schema source.
- `tsconfig.json`: TypeScript paths/strict options and include boundaries.
- `compose.yaml`: Local service composition and runtime env wiring.
- `Dockerfile`: Build and runtime stages for containerized deployment.

**Core Logic:**
- `server/servers.ts`: Server connection, list snapshot, update/delete, credential handling strategy.
- `server/install.ts`: Install lifecycle start + SSE stream endpoint + log retrieval.
- `server/install/sse-stream.ts`: In-memory stream registry, event replay, DB log persistence.
- `server/server-actions.ts`: Restart/update/rollback commands and action audit writes.
- `server/dashboard.ts`: Snapshot aggregation with static+metrics cache and SSH metric polling.
- `server/providers.ts`: Provider save/test/deploy and compose environment injection.
- `server/telegram.ts`: Telegram connect/disconnect/deploy/test workflows.
- `server/server-records.ts`: Shared server lookup, auth-method normalization, credential resolution.

**Testing:**
- `server/*.test.ts`: Backend route/domain tests (e.g., `server/app.test.ts`, `server/install.test.ts`, `server/providers.test.ts`).
- `server/install/sse-stream.test.ts`: SSE stream state and hydration tests.
- `src/features/**/*.test.tsx`: UI behavior tests (dashboard/servers/providers/telegram/logs).
- `src/lib/session.test.ts`: Session guard utility tests.

## Naming Conventions

**Files:**
- kebab-case for most feature and backend modules: `src/features/servers/server-detail.tsx`, `server/server-actions.ts`.
- TanStack route filename conventions: dot segments and dynamic params (`src/routes/servers.index.tsx`, `src/routes/servers.$id.tsx`, `src/routes/servers.$id.install.tsx`).
- `*.test.ts` / `*.test.tsx` colocated with domain code (`server/install.test.ts`, `src/features/servers/install-progress.test.tsx`).

**Directories:**
- Domain-based grouping at both frontend and backend levels: `src/features/servers`, `src/features/providers`, `server/install`, `server/db`.
- Shared infra/util directories named `lib`: `src/lib`, `server/lib`.
- Generated artifacts in dedicated output directories: `drizzle/`, `.tanstack/`, `dist/`.

## Where to Add New Code

**New Feature:**
- Primary code: add route and feature module in `src/routes/` and `src/features/<domain>/`.
- Tests: add UI tests under `src/features/<domain>/*.test.tsx` and API/domain tests under `server/*.test.ts` (or `server/<subdir>/*.test.ts`).

**New Component/Module:**
- Implementation: shared UI in `src/components/` or `src/components/ui/`; backend domain modules in `server/` and shared backend helpers in `server/lib/` or `server/server-records.ts`-style utility modules.

**Utilities:**
- Shared helpers: frontend utilities/types in `src/lib/`; backend utilities/security/data helpers in `server/lib/`, `server/crypto.ts`, `server/credentials.ts`, `server/server-records.ts`.

## Special Directories

**drizzle/:**
- Purpose: SQL migration files and Drizzle metadata.
- Generated: Yes.
- Committed: Yes.

**dist/:**
- Purpose: Build output consumed by production startup script.
- Generated: Yes.
- Committed: No.

**.tanstack/:**
- Purpose: TanStack generated runtime/cache artifacts.
- Generated: Yes.
- Committed: No.

**docs/adr/:**
- Purpose: Architecture decision records for core stack/security choices.
- Generated: No.
- Committed: Yes.
