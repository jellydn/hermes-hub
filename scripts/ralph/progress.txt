## Codebase Patterns
- TanStack Start route types come from the generated `src/routeTree.gen.ts`; run a build or dev server after adding routes so typecheck can see the generated tree.
- This repo uses Bun as the package manager; keep `bun.lock` and do not add `package-lock.json`.
- Reusable UI primitives follow the shadcn layout: place components in `src/components/ui/` and compose class names with the shared `cn()` helper from `src/lib/utils.ts`.
- Shared provider/model catalogs belong in `src/lib/ai-providers.ts` so both the route UI and server-side validation/test handlers read the same defaults and allowed models.
- Authenticated integration pages should fetch their saved summary in a route-level `createServerFn`, then hand that snapshot to a client feature component that owns connect/disconnect form state and follow-up fetch calls.
- Dashboard cards should preload one status snapshot through the route and then poll `/api/dashboard/status` from the client feature so refresh/retry logic stays local without losing SSR coverage.
- Server-side request branching lives in `src/server.ts`; use it to intercept `/api/*` requests and pass all page requests through the default TanStack Start handler.
- `drizzle.config.ts` throws if `DATABASE_URL` is missing, so export that env var before running `drizzle-kit generate` or migration commands.
- Better Auth mounts directly on the Hono app in `server/app.ts`; if the product wants friendlier `/api/auth/*` aliases, implement them as thin request rewrites to Better Auth's built-in routes instead of duplicating auth logic.
- Better Auth setup must stay lazy in this app: construct it through a getter, not at module load, so SSR routes can still render without `DATABASE_URL`, and give the client an absolute auth base URL because Better Auth rejects relative `baseURL` values during SSR.
- Persisted app tables use text primary keys with `gen_random_uuid()::text`, `timestamp(..., { withTimezone: true }).defaultNow()` for timestamps, and explicit foreign-key indexes on relation columns.
- Authenticated dashboard sections should share the `AppShell` from `src/routes/dashboard.tsx` and use `requireSession()` so new pages inherit the same sidebar, header actions, and redirect behavior.
- Nested dashboard routes should follow TanStack's dotted file naming (`src/routes/servers.$id.install.tsx`) so child URLs stay attached to the parent section without hand-written router wiring.
- Field helper and error text should live outside `<label>` elements so accessible names stay predictable in browser automation and component tests.
- Install progress is tracked in the latest `installs` row per server and mirrored through the in-memory SSE stream state in `server/install.ts`; keep persisted log lines and emitted event payloads aligned so reconnecting clients can replay prior progress cleanly.
- Vitest is configured via `vite.config.ts`, so use `bun run test`; plain `bun test` invokes Bun's runner and skips the repo's jsdom-backed test setup.
